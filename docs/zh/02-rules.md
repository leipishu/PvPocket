# 规则规范

> 规范文档 · 中文版。英文版：[`../en/02-rules.md`](../en/02-rules.md)

## 1. 规则模型

一场决斗的规则是一份**有序的键值快照**，由 39 条可配置规则加 1 条只读提示项组成，分七组：

| 组 | 主题 | 条数 |
| --- | --- | --- |
| A | 对局结构（局数、胜负、时间） | 7 |
| B | 参与者（人数、队伍、误伤、观战） | 4 |
| C | 战斗（模式、生存参数） | 7 |
| D | 配装（进场物品、拾取、合成） | 5 |
| E | 场地（尺寸、模板、边界、环境） | 8 |
| F | 方块（放置、破坏、爆炸） | 5 |
| G | 其他（珍珠、投降、显示、聊天） | 4 |

规则定义在 `RuleCatalog`，文本在语言文件（`pvpocket.rule.<id>.label` / `.hint` / `.c<N>` / `.unit`）。
**规则 id 就是线格式**，改名等于改协议；新增规则只能追加，不能重排既有 id。

## 2. 完整清单

格式：`规则 id` · 类型 · 默认值 · 可选值。文本与选项均取自语言文件，与面板显示一致。

**对局结构** — 局数、胜负与时间

- **最多局数** — `a.maxRounds` · 整数 1–15 · 默认 3 局。一场最多打几局，打满即结束。
- **获胜局数** — `a.winsNeeded` · 整数 1–15 · 默认 2 局。先赢到这么多局的一方获胜。面板会把它夹在「最多局数」以内，所以「3 局 4 胜」这种打不到的状态不存在。
  两个数字分开而不是「7 局 4 胜」一个选项，是因为它们回答两个不同的问题：「打满几局收工」和「几局算赢」。合并之后偶数局数表达不了，而且**结构上不可能平局**——胜场由局数推导，总有一方先到线。拆开之后打满仍无人到线就按最高分定胜负，并列即平局。
- **单局时长上限** — `a.roundLimit` · 单选 · 默认 无限制 · 无限制 / 1 分钟 / 3 分钟 / 5 分钟 / 10 分钟 / 15 分钟。超过后按超时判定结算。0 表示无限制。
- **超时判定** — `a.timeoutVerdict` · 单选 · 默认 血量高者胜 · 血量高者胜 / 平局 / 双败。时间耗尽时如何决定这一局。
- **回合准备时间** — `a.countdown` · 整数 0–30 · 默认 5 秒。传送进场后、正式开打前的准备时间，倒计时逐秒显示在聊天栏。准备期间双方无法造成或受到伤害，场地四周会立起一圈白色实心屏障，开打瞬间拆除。
- **局间间隔** — `a.intermission` · 整数 1–10 · 默认 3 秒。多局赛制下两局之间的休整时间。
- **胜利条件** — `a.winConditions` · 多选 · 击杀 / 出界 / 投降 / 超时。这一局可以因哪些原因结束。至少保留一项。

**参与者** — 人数、队伍与误伤

- **每队人数** — `b.teamSize` · 整数 1–5 · 默认 5 人。每方的人数**上限**，也是名册卡片上的空位数。超过则无法开始。
- **总人数上限** — `b.maxPlayers` · 整数 2–20 · 默认 20 人。超过这个人数无法开始。硬上限 20 由 `SessionManager.MAX_PARTICIPANTS` 兜底，两者取小。
- **友伤** — `b.friendlyFire` · 开关 · 默认 关。开启后队友之间可以互相造成伤害。
- **允许观战** — `b.spectator` · 开关 · 默认 开。开启后非参与者可以用 /pvpocket list 看到这一局并点「观战」进入。观战是旁观模式，相机绑定在参与者身上，按 V 切换视角；退出后回到原来的位置。

> **队伍数量不再是一条规则。** 场上有几方，由发起方在名册页上画了几张非空卡片决定——2 到 4 张，空卡片不参与。原先的 `b.teamCount` 只能表达「分成几方」，再让服务端按邀请顺序 round-robin 分人；那样既表达不了「这两个一队、那两个一队」，改数字还会就地重排已经邀请好的名单。现在分队是显式画出来的，规则里就不需要这个数字了。各方人数不必相同。

**战斗** — 战斗模式与生存参数

- **战斗模式** — `c.mode` · 单选 · 默认 现代 · 现代 / 经典 1.8。经典模式关闭攻击冷却，并按 1.8 规则处理格挡、击退与护甲。
- **模式冲突** — `c.modeConflict` · 固定。战斗模式必须全员同意才能开始，不能由发起方单方面决定。
- **最大生命** — `c.maxHealth` · 整数 1–40 · 默认 20 点。进场后双方的生命上限。原版为 20。
- **自然回血** — `c.naturalRegen` · 开关 · 默认 开。关闭后只有药水与金苹果可以回复生命。
- **饥饿消耗** — `c.hunger` · 单选 · 默认 正常 · 正常 / 关闭。关闭后饥饿值不会下降，也不会因饥饿掉血。
- **掉落伤害** — `c.fallDamage` · 开关 · 默认 开。关闭后高处落地不受伤害。
- **击退抗性** — `c.knockbackResistance` · 百分比 · 默认 0%。对所有参与者统一施加的击退抗性。

**配装** — 进场物品与拾取

- **配装归属** — `d.loadoutScope` · 单选 · 默认 每人独立 · 每人独立 / 每队统一。每队统一时，同队成员使用同一套配装。
- **局间可换配装** — `d.allowSwapBetweenRounds` · 开关 · 默认 关。开启后每局开始前可以重新选择配装。
- **允许拾取场地物品** — `d.allowPickup` · 开关 · 默认 关。关闭后无法捡起场地里掉落的物品。
- **允许合成** — `d.allowCrafting` · 开关 · 默认 关。关闭后工作台与背包合成格不可用。
- **允许消耗品** — `d.allowConsumables` · 开关 · 默认 开。关闭后药水、食物、金苹果不可使用。

**场地** — 场地、边界与环境伤害

- **场地长度** — `e.sizeX` · 整数 16–160 · 默认 48 格。场地在 X 方向的格数。选择地图后由地图尺寸接管。
- **场地宽度** — `e.sizeZ` · 整数 16–160 · 默认 48 格。场地在 Z 方向的格数。选择地图后由地图尺寸接管。
- **场地高度** — `e.sizeY` · 整数 8–96 · 默认 32 格。场地在 Y 方向的格数，决定可搭建的垂直空间。选择地图后由地图尺寸接管。
- **场地模板** — `e.template` · 单选 · 默认 平坦 · 平坦 / 游乐屋 / 浮岛 / 暗星云 / 枯木镇 / 斗兽场。「平坦」是一块悬空平台，尺寸就是下面填的长宽；其余为内置地图，选中后场地尺寸自动跟随地图包围盒。所有场地都浮在虚空里，掉出场地就是掉进虚空。同一张地图同一时间只能有一场决斗，正在使用中的地图会标出来并跳过。
- **边界规则** — `e.boundary` · 单选 · 默认 拉回 · 拉回 / 倒计时判负。拉回：越界即被放回最近的边境内。判负：越界开始 5 秒倒计时，结束仍在场外就输掉本局。场地四边会画一圈半透明光幕标出边界（蓝=拉回，红=判负），光幕可以穿过，高度会随你所在的高度长高，并且只画你附近的一段。有内场的图（如斗兽场）只圈中间的战斗区，不算看台。
- **时间** — `e.timeOfDay` · 单选 · 默认 自然 · 自然 / 清晨 / 正午 / 黄昏 / 午夜。固定时间后场地时间不再流逝，昼夜循环关闭；「自然」保留原版循环。
- **天气** — `e.weather` · 单选 · 默认 晴朗 · 晴朗 / 降雨 / 雷暴。每局开始时设定。天气是维度级属性，多场同时进行时以最后一局为准。
- **环境危害** — `e.hazard` · 多选 · 无 / 掉落伤害 / 岩浆 / 虚空。场地内生效的额外伤害来源。

**方块** — 放置、破坏与爆炸

- **允许放置方块** — `f.allowPlace` · 开关 · 默认 关。开启后可以在场地内放置白名单内的方块。
- **地形保护** — `f.protectTerrain` · 开关 · 默认 开。开启后地图本身的方块不可破坏，只有本局放置的方块能拆。关闭后可以挖穿场地，本局结束时地形仍会复原。
- **允许拆除自己放置的方块** — `f.allowBreakOwn` · 开关 · 默认 开。只对本次对局中放置的方块生效，场地本体是否可破坏由「地形保护」决定。
- **方块限制** — `f.blockFilter` · 多选 · 床 / 重生锚 / TNT / 流体桶 / 末地水晶。选中的项目会被禁止使用。默认禁掉床、重生锚、TNT 与流体桶。
- **允许爆炸物** — `f.allowExplosives` · 开关 · 默认 关。关闭后 TNT、苦力怕与末地水晶不产生爆炸。

**其他** — 珍珠、投降与显示

- **允许末影珍珠** — `g.enderPearl` · 开关 · 默认 关。关闭后末影珍珠无法投掷。
- **允许投降** — `g.allowSurrender` · 开关 · 默认 开。关闭后只能通过击杀或超时结束这一局。
- **显示对手血量** — `g.showOpponentHealth` · 开关 · 默认 开。在界面上方显示对手的生命值。
- **决斗中聊天** — `g.chatScope` · 单选 · 默认 全服 / 仅队友 / 禁言。限制对局期间的聊天可见范围。

## 3. 执行状态（重要）

**面板上全部 39 条都可配置、都会写入会话并进日志，其中 20 条在当前版本真正影响对局。**
这一节是本文档最需要读的部分——不要看着面板以为整套规则都生效了。

判定方法：规则 id 在 `RuleCatalog` 之外是否还有读取点。实测结果如下。

### 已生效（20 条）

| 组 | 规则 |
| --- | --- |
| A | `a.maxRounds`、`a.winsNeeded`、`a.countdown`、`a.intermission` |
| B | `b.teamSize`、`b.maxPlayers`、`b.friendlyFire`、`b.spectator` |
| C | `c.mode`、`c.maxHealth` |
| E | `e.template`、`e.sizeX`、`e.sizeY`、`e.sizeZ`、`e.boundary`、`e.timeOfDay`、`e.weather` |
| F | `f.protectTerrain`、`f.allowBreakOwn` |
| G | `g.allowSurrender` |

A 组的两条是本次拆开赛制后接上的，B 组的四条是随 NvN 一起接上的，各自的读取点：

- **`a.maxRounds` / `a.winsNeeded`** — `seriesDecided` 在每局结束时先看局数是否打满、再看有没有人
  到线；打满且无人到线时由 `leaderTeam` 取最高分，并列即 `seriesEndReason = "DRAW"`。两者在
  `applyRulesToSession` 里互相夹取（`winsNeeded = min(winsNeeded, maxRounds)`），面板也做同样的夹取，
  所以打不到的胜场数不会进到会话里。
- **`b.teamSize`** — 每方人数上限，`submitRoster` 在邀请发出前逐个队检查，`validateRoster` 在开局前
  再查一次；超过就拒绝并说明是哪一队超了。它同时也是名册卡片上的空位数，改它会立刻改变卡片高度。
- **`b.maxPlayers`** — 总人数上限，同样在 `submitRoster` / `validateRoster` 里。硬上限 20 由
  `SessionManager.MAX_PARTICIPANTS` 兜底，两者取小。
- **`b.friendlyFire`** — 关闭时同队互相伤害被 `ServerLivingEntityEvents.ALLOW_DAMAGE` 否决，
  并在日志里留一条 `FRIENDLY_FIRE_BLOCKED`。只拦直接攻击者（近战、箭、三叉戟、TNT），不拦
  队友放的火的后续燃烧，这条界线与原生队伍的判定一致。

### 仅记录（19 条）

`a.roundLimit`、`a.timeoutVerdict`、`a.winConditions`、`c.naturalRegen`、`c.hunger`、
`c.fallDamage`、`c.knockbackResistance`、`d.loadoutScope`、`d.allowSwapBetweenRounds`、
`d.allowPickup`、`d.allowCrafting`、`d.allowConsumables`、`e.hazard`、`f.allowPlace`、
`f.allowExplosives`、`f.blockFilter`、`g.enderPearl`、`g.chatScope`、`g.showOpponentHealth`

这些规则写进了 `DuelSession.rules` 与会话日志，没有任何代码读取。它们在面板上可以改、会被
写入规则摘要、会随双方同意一起冻结，但对局行为不受影响。

另有 1 条不是配置项：`c.modeConflict` 是 `fixed` 类型，只用来在面板上说明「1.8 模式与某些
规则冲突」，没有取值可言。

其中三条的落差最容易误导人，单独说明：

- **`a.roundLimit` + `a.timeoutVerdict`**：面板承诺「超过后按超时判定结算」，实际没有计时器。
  两边都不动手时这一局可以无限打下去，只能靠认输或掉线结束。
- **`a.winConditions`**：可以在这里取消「击杀」，但击杀仍然会结束这一局。
- **`f.allowPlace`**：默认关闭，但**关闭状态下依然可以放方块**——方块放置没有任何拦截，
  只有破坏被 `PlayerBlockBreakEvents.BEFORE` 否决。所有方块变化都会在结算时回滚，所以不会
  污染下一局，只是这条开关本身不成立。

**为什么保留**：删掉它们会让规则摘要与实际协议脱节，而补上执行逻辑的工作量分散在多个切片里
（计时器、方块变更集、聊天过滤）。保留「已声明但未执行」的状态比删掉再重新加回来更容易收敛，
但**在对外宣传功能时必须以本节为准**。

## 4. 赛制换算

赛制是两个独立的数字，不再是一个「几局几胜」的选项：

| 设定 | `a.maxRounds` | `a.winsNeeded` | 结果 |
| --- | --- | --- | --- |
| 单局定胜负 | 1 | 1 | 打完一局就结束 |
| 三局两胜 | 3 | 2 | 有人到 2 局即胜；1-1 打完第三局必有人到 2 |
| 七局四胜 | 7 | 4 | 经典 BO7 |
| 三局三胜 | 3 | 3 | 必须 3-0；2-1 打满后按最高分定胜负 |
| 两局一胜 | 2 | 1 | 赢一局就走，可能只打一局 |

**打满即结束。** 局数到达 `a.maxRounds` 后无论比分如何都收工：有人到线就是他赢，没人到线就取最高分，并列即平局（日志记 `SERIES_DRAWN`，结算行写「平局」）。

上限 15 局：再多的话一场决斗会超过一小时，而模组的定位是「生存服里随时能打的一场」，不是联赛。

## 5. 协商与冻结

1. 发起方 `/pvpocket duel` 创建会话（`DRAFT`），规则取默认值，面板以**名册页**（标签页第 0 个）打开。
2. 发起方在名册页上画卡片：默认两张，最多四张，每张 `b.teamSize` 个空位，右上角 `+` 打开玩家选择器。
   空卡片意味着这一方不参与；至少两张非空才能发送。
3. 「发送邀请」把名册和当前规则一起发出：服务端校验队数 2–4、每队不超员、总数不超上限、没有重复、
   被邀请人在线且空闲、发起人自己在名单里——**并且用刚发过来的规则校验**（不是草案打开时的默认值）。
   通过后非空卡片压实成连续队伍索引，进入 `NEGOTIATING`。
4. 所有被邀请的人同时收到面板，打开时同样落在名册页，可看到自己在哪一方、谁还没回应（灰点=待回应，
   绿点=已同意，红点=已拒绝）。名册对接受方只读。
5. 「同意并开始」= 同意这份规则**和所有人的配装**。配装指纹一并记入会话；任一方在此之后改过配装，
   同意失效，面板重新打开。
6. **所有人都做出回应、且剩下的非空队 ≥ 2，才开打。** 拒绝不是取消对局，只是把自己从名单上划掉：
   邀请四个人、一个人拒绝，剩下三个人分两队照样能开；只有剩下的非空队不足 2 时才作废整场。
7. 规则冻结（`FROZEN`），进入传送与快照阶段。

规则快照带版本号（`rulesRevision`），面板右上角显示。任何一次「发送征询」都递增版本，
旧版本上的同意自动作废——这是防止「我同意的是上一版」的唯一手段。
