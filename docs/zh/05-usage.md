# 使用指南

> 规范文档 · 中文版。英文版：[`../en/05-usage.md`](../en/05-usage.md)

## 1. 部署

### 服务端

1. Fabric Loader 0.16.9+，Minecraft 1.21.1，Java 21。
2. 把 `pvpocket-*.jar` 与 [Fabric API](https://modrinth.com/mod/fabric-api) 放进 `mods/`。
3. 首次启动会在存档下生成 `pvpocket/` 目录（`journal`、`homes.json`、`guard.json`、
   `stats`、`history`）。
4. 决斗维度在服务端启动时自动加载并预热，5 张内置图逐 tick 贴好约需 10 秒。
   期间 `/pvpocket arena` 显示「分区尚未布置」，此时无法开局。

**客户端必须装同一个模组。** 没有客户端就没有规则面板、配装编辑器和计分板。

### 权限

| 指令 | 需要 |
| --- | --- |
| 绝大多数 `/pvpocket` 子指令 | 无（任何玩家） |
| `/pvpocket guard <bool>` | OP 等级 2 |
| `/pvpocket arena reset` | OP 等级 3 |
| `/pvpocket arena copy <map> [count]` | OP 等级 3 |
| `/pvpocket arena remove <map> [count]` | OP 等级 3 |
| 主页「管理」页 | OP 等级 3 |

## 2. 玩家流程

### 主页面

两个入口，等价：

- 快捷键 `B`（可在主页面「设置」页改，改动直接写进原版按键设置，原版「按键绑定」里能看到也能改回去）
- 背包界面左侧的「决斗」按钮

快捷键只在**没有任何界面打开时**生效。这是刻意的：规则草案开着的时候按 `B` 会把草案盖掉，
而草案的改动还没发送出去，关掉主页面也找不回来。

五个页签：

| 页签 | 内容 |
| --- | --- |
| 首页 | 问候、一句随机鼓励、一个主按钮（发起决斗 / 继续未开始的对局 / 认输 / 退出观战，按当前状态变）、进行中的对局列表（可直接观战） |
| 数据 | 总场次、胜率、总伤害、KD、小局胜场、最长连胜，以及最近十场的胜负方块 |
| 历史 | 近期对局：比分、胜负、地图、模式、人数、每小局结果；点开看逐局详情，可复制一行结果；底部翻页，每页条数在设置里定 |
| 预设 | 本机的配装与规则预设，可直接开局、分享、导入、删除 |
| 设置 | 版本、许可、配置目录、亮/暗主题、动效开关、比分板大小、结算界面开关、历史每页条数、按键重绑 |

顶栏右侧是当前日期、星期与时间。

**数据属于这个服务器。** 生涯计数与历史存在**存档**里的 `pvpocket/stats`、`pvpocket/history`，
换一个服务器就是另一份，退出服务器时面板立刻清空。这是有意的：两个服务器的胜率没有可比性。

统计口径：

- **总伤害**是打出去的血量，已过护甲、未过吸收。打在还剩 3 点血的人身上的 20 点伤害记 20，
  不按剩余血量截断——否则「总伤害」取决于最后一刀怎么落，而不是打得有多重。
- **击杀**在死亡瞬间用攻击者归属。摔死、自爆、被环境杀死不计给任何人；同队互杀不计。
- **小局胜场**按每个小局的胜方记，跨系列赛累计。
- **最长连胜**是历史最高水位，输一场不会把它减回去，只把当前连胜清零。
- 历史每人保留最近 200 场，超出的旧记录丢弃；生涯计数不清零。

### 开一场

1. 甲：主页面点「发起决斗」，或 `/pvpocket duel` → 规则面板弹出，落在**玩家页**（标签页第一个）。
   页面上默认两张队伍卡片，
   每张有 `b.teamSize` 个空位，卡片顶上是这一方的羊毛色。
2. 甲：点卡片右上角的 `+`，从弹窗里挑人加进这一方；卡片下面「+ 添加队伍」最多加到 4 张。
   空卡片表示这一方不参与，至少两张有人才能发送。人数不必平均。
3. 甲：切到 A/B/… 各页改规则，也可点「编辑配装」先配物品，然后点「发送邀请」。
4. 所有被邀请的人同时收到面板，打开就在玩家页，能看到自己在哪一方、谁还没回应。
5. 每个人各自选「同意并开始」/「修改后征询」/「拒绝」。**全部人都做出回应、且剩下的队伍还够两队时开打。**
   拒绝只是把自己从名单上划掉：邀请四个人、一个人拒绝，剩下三个人分两队照样能开。
6. 开打后各方被传送进场地，倒计时结束后开始。
7. 全部回合结束，所有人回到进入前的位置，物品与场地复原。

面板被 Esc 关掉后，用 `/pvpocket review` 重新打开——这是唯一的回头路。发起方在草案阶段关掉面板
等于取消这次邀请。

### 预设与分享码

三个地方能打开预设列表：主页面「预设」页、规则面板标题行右端的「预设」链接、配装编辑器里的同名
链接。配装和规则各存各的，互不通用。

- **保存**：填个名字再点「保存」，写进 `config/pvpocket/presets.json`。同名的直接覆盖。
- **载入**：把预设填回面板，**不等于提交**——规则仍要点「发送邀请」、配装仍要点「保存配装」。
- **从预设开局**：主页面「预设」页每行右端有「开始」。规则预设直接开一局草案并套上这套规则，
  配装预设开一局草案并把你这一方的配装换掉；之后照常发邀请。
- **删除**：主页面「预设」页每行的「更多」→「删除」，要按两次。
- **分享**：点这一行的「分享」，服务器生成一个 6 位分享码，5 分钟内有效，并已复制到剪贴板。
- **导入**：把别人的码粘进「分享码」再点「导入」。预设**立刻落到本地**，之后不再需要那个码。

规则预设**不含人和队伍**：载入它只换设置，名册卡片原样保留——分队是关于这一场、这些人的决定，
一个能重新安排座位的预设就是能改别人队伍的预设。

预设存在本机，不跟服务器走：换一个服务器，你的预设还在。分享码是内存里的临时传输物，5 分钟后
服务端自己清掉；抄码时大小写、空格和短横线都不影响。

### 配装面板是一份草稿

改配装不会立刻生效：面板里做的每一步（加一件、改一个数、删一行）都只改这份草稿，点「保存配装」才发给
服务器。面板上有三处提示——这一行左边缘的橙条表示它和已保存的不一样，四个页面标签上的橙点表示这一页
有未保存的改动，底部状态行写「未保存」。

**带未保存的改动离开会先问一句**（「保存并返回」/「放弃修改」），Esc 与「返回」都是如此；在问句上再按
一次 Esc 是留在面板。此前 Esc 直接离开、什么都不保存，看起来却像已经保存过了。

**配装只有一份。** 面板可以从主页面打开，也可以从对局面板打开，但保存的是同一份东西：下一场开局、
下一份邀请，用的都是它。改动只在「保存配装」那一刻生效，之后一直算数。

### 配装物品的锁定

配装编辑器里每一条物品的最后一行是「禁止丢弃」，**默认开启**。开着的时候，按 Q 丢不掉这条物品发出
来的东西——拿在手上按 Q 不动，打开背包在格子上按 Q 也不动，两种都只在聊天栏给一句「这件物品已锁定，
不能丢弃」。

- **只作用于配装发出来的那一份。** 锁定写在物品自己身上，不是按格子记的：挪到别的格子、放进箱子、
  被捡起来再捡回去，都还是锁着。这一行附带的箭矢、黑曜石、打火石同样被锁；地上捡的、合成出来的、
  地图里拿到的普通物品不受影响，照常能丢。
- **Ctrl+Q 一次扔整摞也一样被拦。** 拦的是「按 Q 丢弃」这个动作，不是某一种数量。
- **拖出背包窗口丢到地上不拦。** 那要按住鼠标拖到窗口外面，不是一次误触；拦它就成了拦「移动物品」。
- 关掉之后这条物品与普通物品没有区别。这个开关随配装一起保存，也一起进分享码。
- **关掉之后按「保存配装」，手里那件立刻就能丢。** 锁定是发物品时盖在物品上的戳，所以保存时会按新
  配装把背包里本模组发出来的东西重新盖一遍——不然要等下一局重新发物品才生效，看起来就像开关没用。
  只改开关不按保存则什么都不会发生：面板是一份草稿，草稿不发给服务器。

### 观战

`/pvpocket list` 打开对局面板，点「观战」以旁观模式进入。观战中：

- `V` 在参与者之间切换视角
- `G` 解除附身，回到自由飞行
- 自由飞行被限制在场地包围盒外扩 12 格的范围内
- 退出：对局面板里点「退出」，或 `/pvpocket spectate leave`

附身后屏幕底部出现横条（`观战 · <地图> · 第 N 局` + 视角切换提示），快捷栏显示被附身者的九格
与「名字 · HP · 护甲」。原版在旁观模式下完全不画手（`GameRenderer.renderHand` 直接跳过），所以
手持物是模组自己按原版 `HeldItemRenderer` 的变换重画的——主副手分开、空手画手臂、挥手弧线与装备
偏移都照抄，和那个人自己屏幕上看到的逐像素一致。

退出观战会把游戏模式、维度、坐标朝向还回去；背包、效果、经验从未被动过，不需要还。

对局默认允许观战，发起方可以在规则面板 B 组关掉。

### 结算

一整个系列赛打完（不是一小局），每个参赛者都会收到一张结算卡片。它是服务端推的，不需要打开任何
面板；`Esc` 关掉，回到游戏。

卡片从上到下：

- **顶部一行结论**，中文下一行是同义的英文——这是这个模组里最可能被截图发给别人的一屏，所以它
  自带两种语言。输了写「再接再厉 / Well fought!」，平局写「势均力敌 / Evenly matched」，都不写
  「失败」：比分就在下面，同一件事不需要说两遍。
- **每一方一行**：羊毛色的边条、这一方的名单、这一方赢下的小局数。你自己那一方整行有底色，
  名字后面标「你」。
- **逐局战绩**，两列：第几局、胜/负/平、怎么结束的（击杀 / 出界 / 掉线 / 超时判定…）、打了多久。
  列不下时最后一行说「另 N 局未显示」——一张悄悄丢掉四局的卡片比一张承认的卡片更糟。
- **底部**：地图、模式、人数、总用时，以及时间和结束原因（认输 / 中断 / 平局）。

「导出海报」把同一张卡片**铺满整个视口重画一遍**——没有背景遮罩、没有世界、没有按钮——然后
把帧缓冲存成 PNG：

```
screenshots/pvpocket/result-2026-11-10_20-43-07.png
```

分辨率跟着窗口和 GUI 缩放走：1280×720 窗口在缩放 3 下就是 1280×720 的图，字号是面板的 1.0×
（位图字体不在非整数缩放下重采样，所以清楚）。海报比面板高，15 局的长系列赛在面板上可能只放得
下 6 局，在海报上放得下全部。

不想看到它就在「设置 → 对局 → 结算界面」关掉。开关是**本机**的，跟账号走不了——服务端照常把
卡片发给每个参赛者，画不画由客户端自己决定。

## 3. 指令表

指令面刻意收敛：**规则面板能做的事不提供指令**。征询、接受、拒绝只有面板一条路。

主页面不取代指令。它能做的事（发起决斗、从预设开局、观战、退出观战）都仍然有指令入口，
因为控制台和 RCON 没有客户端，脚本和运维也只能走指令。

| 指令 | 作用 |
| --- | --- |
| `/pvpocket help` | 显示帮助（等价于无参 `/pvpocket`） |
| `/pvpocket duel` | 打开规则面板，在面板里挑人、分队、定规则；不带任何参数 |
| `/pvpocket review` | 重新打开规则面板 |
| `/pvpocket surrender` | 认输（输掉整场，不是单局） |
| `/pvpocket status` | 查看当前对局的阶段、回合、比分与规则摘要 |
| `/pvpocket list` | 打开对局面板 |
| `/pvpocket spectate <id 前缀>` | 不进面板直接进入观战 |
| `/pvpocket spectate leave` | 退出观战 |
| `/pvpocket loadout` | 打印配装明细、指纹与校验结果 |
| `/pvpocket loadout edit` | 打开配装编辑器（无需对局） |
| `/pvpocket loadout give` | 把配装发到手上（测试用） |
| `/pvpocket loadout accept` | 同意对手提出的局间配装改动（需规则开启） |
| `/pvpocket loadout decline` | 拒绝对手提出的局间配装改动，沿用原配装 |
| `/pvpocket loadout reset` | 清空个人配装，回到默认预设 |
| `/pvpocket arena` | 场地分区占用、变更数、进行中的对局 |
| `/pvpocket arena reset` | 强制结束所有对局并重建整个场地维度（OP 3） |
| `/pvpocket arena copy <map> [count]` | 给某张地图多分几个场地分区，让更多房间能同时开打（OP 3） |
| `/pvpocket arena remove <map> [count]` | 收回某张地图的分区并清空它，删光后这张图就选不了了（OP 3） |
| `/pvpocket guard <true\|false>` | 开关「滞留决斗维度自动移出」，按玩家记录（OP 2） |

对局面板最多显示 6 场，超出的部分会提示用 `/pvpocket spectate <id>` 进入。

## 4. 运维

### 滞留保护

玩家在决斗维度里既不是参与者也不是观战者时（误入、或对局中途崩服），5 秒后会被送回
进入该维度之前的位置。提示里的 `[ 不要移出 ]` 按钮等价于执行 `/pvpocket guard false`。

```bash
/pvpocket guard false   # 关掉自动移出，进去检查
/pvpocket guard true    # 检查完恢复
```

豁免**按玩家记录**并持久化到 `<world>/pvpocket/guard.json`，重启后仍然有效。
按玩家而不是全局，是因为全局开关一次忘记恢复就等于对所有人关掉了保护。

按钮只对 OP 等级 ≥2 绘制——等级不够的玩家点了会得到「未知指令」，画出来反而更困惑。

### 场地重建

场地出现可疑损坏（方块状态错乱、结构残缺）时：

```bash
/pvpocket arena reset
```

它会：强踢所有观战者 → `abort` 所有进行中的对局（不是结算，不颁奖）→ 送走所有还留在维度里的人
→ 清空维度 → 逐 tick 重贴全部地图。执行期间会向全服播报，因为服务器会静默几秒，
没有提示的话读起来像崩溃。重建完成前无法开新局。

### 场地不够用

一张地图同时只能开「它拥有的分区数」场决斗，多出来的开局请求会被拒、面板上那张图会灰掉。
默认平坦图 4 份、斗兽场 2 份、其余 1 份。要加：

```bash
/pvpocket arena copy flat 2            # 再给平坦图两份
/pvpocket arena copy arena_colosseum   # 不写数量就是一份
/pvpocket arena remove flat            # 收回一份，格子清空、还给网格
```

副本拿到的是**固定格子编号**，记在 `<world>/pvpocket/arena.json`，重启也不会挪，
所以可以用 `/tp` 记住位置。非平坦地图的副本在下命令时就贴好；平坦图的副本只占位，
第一场落在它上面的决斗才按规则尺寸铺地。网格一共 16 个格子，满了就只能换更大的维度。

`remove` 从**最后加的那份**开始收，所以其余副本的地址不会动；正在打的格子会被跳过，
全在打就拒绝（等这一场结束）。**没有下限**：删光以后这张图就从规则面板里消失了，
再按「复制」它会回到自己原来的地址，而不是网格末尾的新格子。
细节见 [`06-maps.md`](06-maps.md#5-场地分区与副本)。

### 管理页

OP 等级 3 的玩家打开主页（默认按键 `B`）后，侧栏会多出一页「管理」，就在设置上面：

| 控件 | 等价于 |
| --- | --- |
| 每张图右侧的「复制」 | `/pvpocket arena copy <map>` |
| 每张图右侧的「删除」 | `/pvpocket arena remove <map>` |
| 「重建场地」 | `/pvpocket arena reset`（先弹确认框，并告诉你会结束几场对局） |
| 「滞留保护」开关 | `/pvpocket guard true\|false` |

「删除」不弹确认框：它不会结束任何对局（有对局的分区按钮直接是灰的），而且旁边那个
「复制」就能把它加回来。真正的确认留给会打断别人的「重建」。

分区表读的是实时快照：复制成功、重建开始、开关翻转之后，服务端会重新发一份，页面跟着变。
面板只是同一段服务端代码的另一个入口，权限在服务端校验——面板不画按钮是方便，不是锁。

### 沙盒规则

决斗维度内，玩家聊天只能发 `/pvpocket` 开头的指令，且任何人不得自行切换游戏模式。
控制台、RCON、命令方块不受此限制——运维需要能救卡住的玩家。

## 5. 排障

| 现象 | 先看什么 |
| --- | --- |
| 面板没弹出 | 服务端日志里 `Rules panel -> <玩家> (canSend=…)`；`false` 说明客户端没声明通道（模组版本不一致） |
| 主页面按钮是灰的 | 服务端没声明主页面协议（模组版本不一致）。按钮的提示会写「当前服务器不支持主页面协议」 |
| 数据页一直是空的 | 数据从第一场打完开始记；正在进行的对局不计入，结算后才写 |
| 换了服务器数据没了 | 正常。计数与历史属于存档，不属于玩家账号 |
