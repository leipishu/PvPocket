# 使用指南

> 规范文档 · 中文版。英文版：[`../en/05-usage.md`](../en/05-usage.md)

## 1. 部署

### 服务端

1. Fabric Loader 0.16.9+，Minecraft 1.21.1，Java 21。
2. 把 `pvpocket-*.jar` 与 [Fabric API](https://modrinth.com/mod/fabric-api) 放进 `mods/`。
3. 首次启动会在存档下生成 `pvpocket/` 目录（`journal`、`homes.json`、`guard.json`）。
4. 决斗维度在服务端启动时自动加载并预热，5 张内置图逐 tick 贴好约需 10 秒。
   期间 `/pvpocket arena` 显示「分区尚未布置」，此时无法开局。

**客户端必须装同一个模组。** 没有客户端就没有规则面板、配装编辑器和计分板。

### 权限

| 指令 | 需要 |
| --- | --- |
| 绝大多数 `/pvpocket` 子指令 | 无（任何玩家） |
| `/pvpocket guard <bool>` | OP 等级 2 |
| `/pvpocket arena reset` | OP 等级 3 |

## 2. 玩家流程

### 开一场

1. 甲：`/pvpocket duel` → 规则面板弹出，落在**玩家页**（标签页第一个）。页面上默认两张队伍卡片，
   每张有 `b.teamSize` 个空位，卡片顶上是这一方的羊毛色。
2. 甲：点卡片右上角的 `+`，从弹窗里挑人加进这一方；卡片下面「+ 添加队伍」最多加到 4 张。
   空卡片表示这一方不参与，至少两张有人才能发送。人数不必平均。
3. 甲：切到 A/B/… 各页改规则，也可点「编辑配装」先配物品，然后点「发送邀请」。
4. 所有被邀请的人同时收到面板，打开就在玩家页，能看到自己在哪一方、谁还没回应。
5. 每个人各自选「同意并开始」/「修改后征询」/「拒绝」。**全部人都做出回应、且剩下的队伍还够两队时开打。**
   拒绝只是把自己从名单上划掉：邀请四个人、一个人拒绝，剩下三个人分两队照样能开。
6. 开打后各方被传送进场地，倒计时结束后开始。
7. 全部回合结束，所有人回到进入前的位置，物品与场地复原。

面板被 Esc 关掉后，用 `/pvpocket review` 重新打开——这是唯一的回头路。发起方在草案阶段关掉面板
等于取消这次邀请。

### 观战

`/pvpocket list` 打开对局面板，点「观战」以旁观模式进入。观战中：

- `V` 在参与者之间切换视角
- `G` 解除附身，回到自由飞行
- 自由飞行被限制在场地包围盒外扩 12 格的范围内
- 退出：对局面板里点「退出」，或 `/pvpocket spectate leave`

附身后屏幕底部出现横条（`观战 · <地图> · 第 N 局` + 视角切换提示），快捷栏显示被附身者的九格
与「名字 · HP · 护甲」。原版在旁观模式下完全不画手（`GameRenderer.renderHand` 直接跳过），所以
手持物是模组自己按原版 `HeldItemRenderer` 的变换重画的——主副手分开、空手画手臂、挥手弧线与装备
偏移都照抄，和那个人自己屏幕上看到的逐像素一致。

退出观战会把游戏模式、维度、坐标朝向还回去；背包、效果、经验从未被动过，不需要还。

对局默认允许观战，发起方可以在规则面板 B 组关掉。

## 3. 指令表

指令面刻意收敛：**规则面板能做的事不提供指令**。征询、接受、拒绝只有面板一条路。

| 指令 | 作用 |
| --- | --- |
| `/pvpocket help` | 显示帮助（等价于无参 `/pvpocket`） |
| `/pvpocket duel` | 打开规则面板，在面板里挑人、分队、定规则；不带任何参数 |
| `/pvpocket review` | 重新打开规则面板 |
| `/pvpocket surrender` | 认输（输掉整场，不是单局） |
| `/pvpocket status` | 查看当前对局的阶段、回合、比分与规则摘要 |
| `/pvpocket list` | 打开对局面板 |
| `/pvpocket spectate <id 前缀>` | 不进面板直接进入观战 |
| `/pvpocket spectate leave` | 退出观战 |
| `/pvpocket loadout` | 打印配装明细、指纹与校验结果 |
| `/pvpocket loadout edit` | 打开配装编辑器（无需对局） |
| `/pvpocket loadout give` | 把配装发到手上（测试用） |
| `/pvpocket loadout accept` | 同意对手提出的局间配装改动（需规则开启） |
| `/pvpocket loadout decline` | 拒绝对手提出的局间配装改动，沿用原配装 |
| `/pvpocket loadout reset` | 清空个人配装，回到默认预设 |
| `/pvpocket arena` | 场地分区占用、变更数、进行中的对局 |
| `/pvpocket arena reset` | 强制结束所有对局并重建整个场地维度（OP 3） |
| `/pvpocket guard <true\|false>` | 开关「滞留决斗维度自动移出」，按玩家记录（OP 2） |

对局面板最多显示 6 场，超出的部分会提示用 `/pvpocket spectate <id>` 进入。

## 4. 运维

### 滞留保护

玩家在决斗维度里既不是参与者也不是观战者时（误入、或对局中途崩服），5 秒后会被送回
进入该维度之前的位置。提示里的 `[ 不要移出 ]` 按钮等价于执行 `/pvpocket guard false`。

```bash
/pvpocket guard false   # 关掉自动移出，进去检查
/pvpocket guard true    # 检查完恢复
```

豁免**按玩家记录**并持久化到 `<world>/pvpocket/guard.json`，重启后仍然有效。
按玩家而不是全局，是因为全局开关一次忘记恢复就等于对所有人关掉了保护。

按钮只对 OP 等级 ≥2 绘制——等级不够的玩家点了会得到「未知指令」，画出来反而更困惑。

### 场地重建

场地出现可疑损坏（方块状态错乱、结构残缺）时：

```bash
/pvpocket arena reset
```

它会：强踢所有观战者 → `abort` 所有进行中的对局（不是结算，不颁奖）→ 送走所有还留在维度里的人
→ 清空维度 → 逐 tick 重贴全部地图。执行期间会向全服播报，因为服务器会静默几秒，
没有提示的话读起来像崩溃。重建完成前无法开新局。

### 沙盒规则

决斗维度内，玩家聊天只能发 `/pvpocket` 开头的指令，且任何人不得自行切换游戏模式。
控制台、RCON、命令方块不受此限制——运维需要能救卡住的玩家。

## 5. 排障

| 现象 | 先看什么 |
| --- | --- |
| 面板没弹出 | 服务端日志里 `Rules panel -> <玩家> (canSend=…)`；`false` 说明客户端没声明通道（模组版本不一致） |
| 开局被拒「场地正在重建」 | 上一个 `arena reset` 还没贴完，等 `/pvpocket arena` 显示地图数恢复 |
| 开局被拒「正在被另一场决斗使用」 | 同一张图不能开两场，换图 |
| 玩家卡在决斗维度 | `/pvpocket guard false` 后手动 tp，或等他 5 秒被自动移出 |
| 认输无效 | 规则面板 G 组「允许投降」被关掉了 |
| 玩家物品丢失 | 看 `pvpocket/journal/` 里该会话的 `SNAPSHOT_TAKEN` / `RESTORED` 序列 |

日志位置：服务端 `<world>/logs/latest.log`；开发环境客户端 `fabric-1.21.1/build/devlogs/client*.out`。
