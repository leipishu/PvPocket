# 2026-11-04

## PvPocket 第一阶段：模组设想 v0.1

- 产出 `docs/PvPocket-vision-v0.1.md`（产品设想与范围文档，不含代码结构）。
- 核心技术调研结论：
  - CombatEdit（服务端、Apache-2.0、1.19–1.26.x）通过改写实体/物品**默认属性**实现 1.8 战斗，配置模型是服务器全局（settings.json + base profile + profile extension），**不支持按玩家/按对局动态开关**；Old Combat Mod / Classic Combat / Not Coldown 同为全局方案。
  - 因此「生存保持现代 + 决斗内 legacy」必须自研按会话战斗规则层；现有模组的 1.8 配置档案可作为数值基线与回归对照（方案 C 混合）。
  - 1.21.1 攻击冷却在服务端结算、客户端指示器读取攻速属性 → 服务端可按玩家隔离；缺口仅在视觉（剑格挡无姿态、无格挡动作）。
- 关键设计立场：生存数据只存在于快照、沙盒数据只存在于会话，两者只有「冻结」「恢复」两条受控通道；先写日志后改状态；恢复幂等；属性用带会话标识的临时修饰并启动时全量剥离。
- 待用户确认的 9 个决策点（D-01 场地承载方式为首要：世界内区域 vs 口袋维度）。

## 追加：决策点详解

- 产出 `docs/PvPocket-decisions-v0.1.md`，按**可逆性**重排 9 个决策：
  - 不可逆（阶段 2 前必须定）：D-01 场地承载、D-05 崩溃恢复语义、D-09 多人模型
  - 半可逆：D-02 保真度、D-03 客户端策略、D-06 配装权限
  - 可逆（改配置）：D-04 模式冲突、D-07 死亡统计、D-08 场地环境
- 新洞察：
  - D-01 的核心理由是「风险是开放式还是封闭式」——世界内区域的事件拦截清单随模组/版本增长，口袋维度清单封闭。两种选错的性质不同：一个是数据事故，一个是体验缺失。
  - D-02：F1 单独上线会形成「1.8 节奏 + 1.9 数值」的混合体，护甲曲线不对，硬核玩家会指出「伤害不对」。改措辞为「Legacy 1.8 手感」即范围声明。
  - D-05：续赛的真正难点不是「存不存得下」，而是「重建后是否逐项一致」；不一致会产生「看起来公平但实际不公平」的对局。
  - D-08 修正原建议：从「纯平坦」改为「静态地形 + 禁止方块交互」——有地形 ≠ 地形会变，静态地形提供多样性但零还原负担。
  - D-09：数据模型可通用，判定逻辑不可通用 → 预留数据模型、不实现判定逻辑。

## 追加：v0.2 决策锁定（用户已定）

- 产出 `docs/PvPocket-v0.2-方案确认.md`（增量修订文档）。
- 用户决定：口袋维度（可设尺寸，模板后续）；1.8 只做「无冷却 + 右键格挡」；**双端模组**；1.8 需双方同意；创建无需权限（指令指定玩家名）；死亡不计入统计；场地本体不可破坏但允许放置/拆除所放置方块；支持多队（可设队伍数上限与总人数上限）。
- 补充要求：发起者先用 GUI 设全部规则 → 私聊发给所有对象 → 接受/拒绝/**编辑后重新征求意见**；所有 GUI 自绘、不用原版样式、**不引入前置依赖**。
- 我做的关键澄清：
  1. 用户把「崩溃」理解为「死亡后重置」。实际是两个不同流程：回合重置（正常流程）vs 崩溃对账（启动时恢复未归档会话，不可省略）。
  2. 只做无冷却+格挡后「1.8」措辞不再准确，建议改称「经典战斗（无攻击冷却 + 剑格挡）」，验收标准中「击退手感变化」需删除。
- 新增设计：提案版本化协商（编辑即重置所有接受、规则快照冻结、单人单提案、全员同意）；队伍模型（最后存活队伍获胜、个人独立生命、比分按队伍）；方块变更集合（只还原玩家放置的方块、逆序移除、统一入口是唯一攻击面）；自绘 GUI 组件库（估占总工期 25–35%）。
- 待用户确认 4 项：Q-1 崩溃回滚、Q-2 未装客户端可否进服、Q-3 前置依赖边界（是否允许 Fabric API）、Q-4 格挡是否含击退减免。
- MVP 建议按 S1–S6 垂直切片推进，不并行。

## 追加：v0.3 决策终稿 + 1.8 战斗规格

- 产出 `docs/PvPocket-v0.3-战斗规格与终稿.md`。4 项待确认全部关闭：Q-1 崩溃取消对局、Q-2 双端强制、Q-3 允许 Fabric API、D-02 改为**完整 1.8 战斗逻辑**。
- 关键技术结论：**属性覆盖做不了公式**。无冷却可用攻速属性近似，但护甲减伤公式、暴击条件、禁横扫、击退向量、武器伤害表都必须接管伤害结算管线 → 接管点从 2 个增至 8–10 个。
- 1.8 规格分 6 层：L1 攻击节奏、L2 击退、L3 格挡、L4 伤害与护甲、L5 生存节奏(P1)、L6 药水数值(P1)。L2 击退最易「看起来对实际不对」，需逐项位移曲线对照测试。
- 新增两个设计问题：
  1. **属性语义按模式解释**：同一「护甲 20」在 1.8 模式=80% 减伤，现代模式=不同结果。建议配装存语义值、模式决定公式，界面实时显示等效减伤。
  2. **1.8 物品池**：盾牌/三叉戟/重锤/弩/鞘翅在 1.8 无对应语义，应按模式过滤配装物品池，而非静默失效。
- 双端强制四件事：协议版本独立校验、Modrinth/整合包分发、与 Sodium/Iris 共存测试、崩溃责任转移到模组方。
- 数值不凭记忆写：阶段 2 需反编译 1.8.9 建立数值对照表再实现。
- MVP 切片重排 S1–S7：先隔离闭环，再 L1+L3，再 L2+L4，然后协商、队伍、方块、GUI。
