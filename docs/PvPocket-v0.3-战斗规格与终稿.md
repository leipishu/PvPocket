## 1. 范围反转：从"两项"到"完整逻辑"

### 1.1 变化

| | v0.2（你上一条的决定） | v0.3（本次） |
| --- | --- | --- |
| 无攻击冷却 | 做 | 做 |
| 右键剑格挡 | 做 | 做 |
| 击退曲线 | **不做** | **做** |
| 暴击 / 横扫规则 | **不做** | **做** |
| 伤害与护甲公式 | **不做** | **做** |
| 措辞 | 建议改称"经典战斗" | 可以叫"1.8 战斗模式"了 |

### 1.2 这个反转最重要的技术后果

**属性覆盖做不了公式。**

v0.2 之所以能用"属性覆盖"实现，是因为它只需要改数值：把攻速属性调到极高就等于"无冷却"，格挡只是加一个减伤判断。这两件事都可以在不碰原版计算逻辑的前提下完成。

但"按 1.8 的战斗逻辑"要求的是**换掉计算方式**：

| 机制 | 能否用属性覆盖 | 原因 |
| --- | --- | --- |
| 无攻击冷却 | 能 | 攻速属性足够高，冷却时间趋近于零 |
| 格挡减伤 | 能（部分） | 可以在受击事件里改伤害值 |
| 护甲减伤公式 | **不能** | 1.8 是 `伤害 × (1 − 护甲/25)`，现代是含韧性的分段公式。公式不同，不是数值不同 |
| 暴击条件 | **不能** | 1.8 的判定条件与现代不同，需要改判定分支 |
| 禁用横扫 | **不能** | 需要拦掉横扫的生成逻辑，属性管不到 |
| 击退向量 | **不能** | 击退的合成公式（基础值 + 冲刺加成 + 附魔 + 抗性）与现代不同，需要重算 |
| 武器伤害表 | 部分能 | 可用属性修饰符拼出来，但会与配装属性互相覆盖，来源不可辨 |

**结论：1.8 战斗必须走"接管伤害结算管线"的路线，接管点从 2 个变成 8–10 个。**

这意味着 v0.1 里设计的"三道闸"（身份闸 / 局闸 / 清理闸）依然是正确架构，但第一道闸后面的分支不再是一个轻量判断，而是一整套并行的结算逻辑。

### 1.3 代价与补偿

**代价**：实现量约为 v0.2 方案的 2 倍；每一个接管点都是潜在的错误来源；回归测试需要覆盖"现代模式不受影响"这一侧。

**补偿**：双端强制让这件事从"勉强能做"变成"能做好"。1.8 的手感有很大一部分来自客户端即时反馈——攻击立刻有挥击动画、格挡立刻有姿态、击退立刻有位移。纯服务端方案在高延迟下会明显打折，而客户端预测可以把这部分补回来。**这是本次范围反转能够成立的前提。**

## 2. 1.8 战斗规格

分六层。每层标注：**确定性**（确定 / 需核实）、**接管方式**、**是否进 MVP**。

> **关于数值**：本文只定义"哪些机制需要接管、接管到什么程度"，不给出具体数值表。1.8 的精确数值（击退系数、附魔加成、暴击条件细节）应在阶段 2 通过反编译 1.8.9 与社区文档建立一份**数值对照表**，逐项与 1.21.1 对比后再实现。凭记忆写数字是本项目最容易埋雷的地方。

### L1 攻击节奏

| 机制 | 1.8 行为 | 现代行为 | 接管方式 | 确定性 | MVP |
| --- | --- | --- | --- | --- | --- |
| 攻击冷却 | 无，每次点击立即按满值结算 | 按距上次攻击的 tick 数缩放伤害 | 接管伤害入口，跳过冷却缩放 | 确定 | 是 |
| 攻击距离 | 3.0 格（含实体碰撞箱扩展） | 3.0 格，但 eye height 与碰撞箱处理有差异 | 接管命中判定 | 需核实 | 是 |
| 无敌帧 | 受击后 20 tick 内不再受伤，但更高伤害可覆盖 | 同类机制，受冷却影响表现 | 接管受击判定 | 需核实 | 是 |
| 连击 | 每次点击独立结算，无节奏惩罚 | 未充满时伤害按比例衰减 | 随"无冷却"一并生效 | 确定 | 是 |

**客户端配套**：隐藏攻击冷却指示器；攻击时立即播放挥击动画（不等待服务端确认）。

### L2 击退

| 机制 | 1.8 行为 | 现代行为 | 接管方式 | 确定性 | MVP |
| --- | --- | --- | --- | --- | --- |
| 基础击退向量 | 水平与垂直分量按固定系数合成 | 公式不同，含 `attack_knockback` 属性 | 重算击退向量后写入实体速度 | 需核实 | 是 |
| 冲刺攻击加成 | 冲刺时附加额外击退 | 现代有独立的冲刺击退属性 | 接管击退合成 | 确定 | 是 |
| 击退附魔 | 每级追加击退 | 同概念，数值不同 | 接管击退合成 | 需核实 | 是 |
| 击退抗性 | 按比例减免 | 同概念，数值不同 | 接管击退合成 | 需核实 | 是 |
| 格挡时击退 | 减半 | 盾牌机制下不同 | 接管击退合成 | 确定 | 是 |
| 空中受击的垂直分量 | 与地面受击不同 | 与 1.8 不同 | 接管击退合成 | 需核实 | 是 |

**这是六层里最容易"看起来对、实际不对"的一层。** 击退的体感由水平衰减、垂直分量、摩擦系数共同决定，任何一项偏一点，玩家都会觉得"打飞的距离不对"。建议在阶段 2 建立**逐项对照测试**：同一场景下分别录制 1.8 参考服务端与 PvPocket 的位移曲线，做数值比对，而不是靠肉眼看。

### L3 格挡

| 机制 | 1.8 行为 | 现代行为 | 接管方式 | 确定性 | MVP |
| --- | --- | --- | --- | --- | --- |
| 触发 | 右键持剑进入格挡态 | 无（盾牌取代） | 接管右键使用逻辑，建立格挡状态 | 确定 | 是 |
| 减伤 | 受到伤害减半 | — | 接管受击结算 | 确定 | 是 |
| 减击退 | 击退减半 | — | 接管击退合成 | 确定 | 是 |
| 移速惩罚 | 格挡时移动速度下降 | — | 施加临时属性修饰（带会话标记） | 需核实 | 是 |
| 姿态与音效 | 剑横举、格挡音效 | — | **客户端渲染** | 确定 | 是 |
| 退出条件 | 松开右键 / 切换物品 / 受到破防 | — | 状态机 | 确定 | 是 |

**必须定义的边界**：1.8 没有盾牌。如果配装里出现盾牌，1.8 模式下应视为普通物品（无法举起），还是直接从可用物品池排除？建议**排除**，并在配装界面标注原因。

### L4 伤害与护甲

| 机制 | 1.8 行为 | 现代行为 | 接管方式 | 确定性 | MVP |
| --- | --- | --- | --- | --- | --- |
| 武器基础伤害 | 固定伤害表（木剑 4、石 5、铁 6、钻 7） | 基础 1 + 属性修饰符 | 接管伤害入口，按 1.8 表取值 | 确定 | 是 |
| 护甲减伤 | `伤害 × (1 − min(20, 护甲)/25)`，20 护甲 = 80% | 含韧性的分段公式 | 接管减伤计算 | 确定 | 是 |
| 护甲韧性 | 不存在 | 存在 | 1.8 模式下忽略该属性 | 确定 | 是 |
| 附魔减伤（保护类） | 按 EPF 计算，与 1.9+ 不同 | 不同 | 接管减伤计算 | 需核实 | 是 |
| 暴击 | 下落攻击 1.5 倍 | 条件更严格 | 接管暴击判定 | 需核实 | 是 |
| 横扫 | 不存在 | 存在 | 禁用横扫生成 | 确定 | 是 |
| 攻击速度 | 所有武器相同 | 按武器类型区分 | 1.8 模式下忽略攻速属性 | 确定 | 是 |
| 耐久消耗 | 每次命中消耗固定值 | 类似但阈值不同 | 接管耐久结算 | 需核实 | 否（P1） |

### L5 生存节奏

| 机制 | 1.8 | 现代 | MVP |
| --- | --- | --- | --- |
| 自然回血条件与速率 | 与 1.9+ 不同 | — | 否（P1） |
| 饥饿消耗速率 | 与 1.9+ 不同 | — | 否（P1） |

**判断**：这两项对"打架手感"的影响远小于 L1–L4，且与配装里的"饥饿消耗""自然回血"参数耦合。建议 **P1 再做**，MVP 沿用现代规则，并在文档中说明。

### L6 药水与效果数值

| 机制 | 1.8 | 现代 | MVP |
| --- | --- | --- | --- |
| 力量 / 虚弱 / 抗性提升的加成方式 | 固定值加成 | 百分比加成 | 否（P1） |

**判断**：这一层的差异会明显改变对局平衡（力量药水在两种模式下强度差很多）。建议 **P1 做**，但在 MVP 阶段**限制配装可用的效果池**，只开放数值差异小的效果（如速度、跳跃、缓慢），避免"用现代数值模拟 1.8 玩法"造成失衡。

## 3. 一个必须解决的设计问题：属性语义按模式解释

配装里有"护甲值"这个参数。同一个数值在两种模式下含义不同：

| 护甲值 | 1.8 模式减伤 | 现代模式减伤 |
| --- | --- | --- |
| 10 | 40% | 按含韧性公式计算，结果不同 |
| 20 | 80% | 按含韧性公式计算，结果不同 |

这会产生一个隐蔽的公平性问题：**同一个配装在两种模式下强度不同**，而玩家看到的是同一个配装名。

两种处理方式：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A 语义值** | 配装存"护甲点数"，模式决定解释公式 | 配装可跨模式复用；语义直观 | 同一配装在两种模式下强度不同，需要提示 |
| B 双套参数 | 配装分模式存两套数值 | 强度可控 | 配装复杂度翻倍，编辑界面难做 |

**建议 A**，并在配装编辑界面显示"当前模式下等效减伤 62%"这样的实时换算，让差异可见而非隐藏。

## 4. 双端强制带来的工程约束

强制安装把项目从"服务端插件"变成"模组服"，性质变了，需要正面处理四件事。

### 4.1 协议版本校验

- 客户端在握手阶段上报**协议版本 + 模组版本**。
- 服务端严格校验：不匹配则拒绝连接，并给出可读原因（"请更新客户端至 x.y.z"），而不是让玩家进服后遇到各种诡异 bug。
- 协议版本必须独立于模组版本号管理——模组可以修 bug 不改协议，但协议一变就必须强制同步。

### 4.2 分发

- 发布渠道：Modrinth / CurseForge。
- 提供整合包（`.mrpack`），让玩家一键安装，而不是手动丢 jar。
- 服务器列表页/入服提示里写清版本号与下载地址。

### 4.3 兼容性

必须与主流客户端模组共存测试，至少覆盖：渲染优化类（Sodium、Iris）、HUD 类、小地图类。**任何一次崩溃都是服务器事故**，责任从"玩家自己的问题"转移到"你的问题"。

### 4.4 收益

强制安装换来的能力，正好是 1.8 手感最需要的部分：

| 能力 | 作用 |
| --- | --- |
| 攻击的客户端预测 | 点击立即出动画，不等服务端回包，高延迟下不失真 |
| 格挡姿态渲染 | 能看到自己在格挡，也能看到对手在格挡（这是 1.8 PvP 的关键信息） |
| 挥击动画替换 | 1.8 的挥击动作与现代不同，可以做 |
| 击退的本地插值 | 位移更顺滑 |
| 冷却指示器控制 | 完全隐藏，而不是"看起来充满了" |
| 规则/配装 GUI | 自绘面板的前提 |
| 边界与倒计时 HUD | 原生渲染 |

## 5. 1.8 模式下的物品池问题

这是"完整 1.8 逻辑"带来的一个容易被忽略的问题：**现代有 1.8 不存在的物品，它们在 1.8 模式下没有对应语义。**

| 物品 | 问题 | 建议 |
| --- | --- | --- |
| 盾牌 | 1.8 无盾牌，格挡由剑承担 | 1.8 模式下从可用物品池排除 |
| 三叉戟 | 1.8 无此物品，投掷与近战语义都是新的 | 排除 |
| 重锤（Mace） | 1.21 新增，砸击机制 1.8 完全没有 | 排除 |
| 弩 | 1.8 无弩 | 排除 |
| 鞘翅 | 1.8 无 | 排除 |
| 新生效药水 | 1.8 无对应数值 | 按 L6 处理，MVP 限制效果池 |

**实现方式**：配装的"可用物品池"按战斗模式过滤。玩家在 1.8 模式下打开配装编辑，看不到这些物品——而不是放进去之后静默失效。静默失效是最糟的体验。

## 6. 验收标准（第三版）

原五条保持不变，新增 1.8 专项验收。每条都必须可自动化或可复现。

| 编号 | 验收项 | 判定方式 |
| --- | --- | --- |
| A-1 | 生存下攻击有冷却；1.8 决斗中无冷却 | 连续点击 5 次（间隔 100ms），5 次全部造成伤害 |
| A-2 | 击退符合 1.8 参考值 | 固定场景下位移曲线与 1.8 参考服务端偏差 < 5% |
| A-3 | 剑格挡生效 | 右键持剑受击：伤害减半、击退减半、移速下降 |
| A-4 | 暴击按 1.8 条件触发 | 下落攻击 1.5 倍；非下落攻击不暴击 |
| A-5 | 无横扫 | 攻击多个相邻实体时，仅主目标受伤 |
| A-6 | 护甲按 1.8 公式减伤 | 20 护甲承受伤害为原始的 20% |
| A-7 | 同服隔离 | A 在 1.8 决斗中，B 在生存中打怪仍为现代规则 |
| A-8 | 每局重置 | 局末双方耐久、效果、血量回到本局开局 |
| A-9 | 系列赛结束完整恢复 | 与决斗前逐项比对，差异为零 |
| A-10 | 无法复制 | 决斗前后服务器物品总量无净增 |
| A-11 | 崩溃取消对局 | 随机时点杀进程，重启后玩家回到生存快照，系列赛标记作废 |

## 7. 修订后的 MVP 切片

因为 1.8 从"两项"扩到"六层"，切片顺序要重排：**先把隔离做扎实，再做战斗深度**，否则会在一个不可靠的容器里调手感。

| 切片 | 内容 | 验收标志 |
| --- | --- | --- |
| S1 | 2 人 / BO1 / 现代模式 / 平坦场地 / 固定配装 / 完整恢复 / 崩溃取消 | A-8、A-9、A-11 通过 |
| S2 | 1.8 的 L1 + L3（无冷却 + 格挡） | A-1、A-3 通过 |
| S3 | 1.8 的 L2 + L4（击退 + 伤害护甲 + 暴击 + 禁横扫） | A-2、A-4、A-5、A-6 通过 |
| S4 | 规则面板 + 提案协商（接受/拒绝/编辑） | 编辑后全员重新确认的流程正确 |
| S5 | 多人队伍（2 队 × 2 人） | 最后存活队伍获胜，比分正确 |
| S6 | 方块放置与还原 | 局末场地回归生成态，变更集合为空 |
| S7 | 配装编辑 GUI + 局间重置完善 | 每局开局状态与配装定义逐项一致 |

**S2 与 S3 之间必须有一次完整的回归**：确认 S3 的接管点没有破坏 S2 已通过的项。这是最容易出问题的地方——每加一个接管点，都可能影响已通过的机制。
