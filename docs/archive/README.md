# 历史存档

这里放的是**过程文档**：设计阶段的方案草案、每个实现阶段的进度记录、专项调研。它们记录的是
「当时为什么这么判断」，不是「现在该怎么做」。

**本目录下的任何内容都不是规范。** 想知道当前行为，读 [`../zh/`](../zh/)（英文
[`../en/`](../en/)）；想知道改动历史，读 [`../../CHANGELOG.md`](../../CHANGELOG.md)。

三个子目录按文档性质划分，不是按时间。每篇开头都有一段说明：它记了什么、被什么取代了。

## 为什么保留

代码注释只能解释「这一行在做什么」，解释不了「为什么不是另一种做法」。这类论证散落在方案草案
和阶段记录里：某个规则为什么只记录不执行、某个字段为什么不能重排、某条指令为什么被删掉。
规范文档写结论，存档写论证，两者分开是为了让规范保持可读。

代价是这些文档会与代码脱节。**引用其中的路径、指令、类名之前先核对当前代码**——`run/` 已经
变成 `runs/server/`，`/pvpocket accept` 已经不存在，这类漂移在存档里是常态，不做追改。

## 已缩减的内容

- **末尾的「下一步」小节已删除**（S1、S2、S3、S6、S7a、S7b）。那些是对下一阶段的计划，
  现在全部落地，对读者没有任何可执行信息。S4 的「下一步」夹在文中，删除会打乱后续小节编号，
  原样保留。
- **其余内容按原样保留**，包括已被推翻的判断。删掉错误的判断等于删掉「为什么不能那么做」。
