# Maps and assets

> Specification · English. Chinese version: [`../zh/06-maps.md`](../zh/06-maps.md)

## 1. Built-in maps

| Key | Name | Size (X×Y×Z) | Source | Licence |
| --- | --- | --- | --- | --- |
| `flat` | Flat | Determined by rules | Generated at runtime | Own work |
| `arena_fun_house` | Fun House | 82 × 28 × 57 | zzuf `maps/tdm/fun_house` | CC BY-SA 4.0 |
| `arena_earthborn` | Sky Islands | 45 × 34 × 60 | zzuf `maps/gs/gs_earthborn` | CC BY-SA 4.0 |
| `arena_dark_nebula` | Dark Nebula | 87 × 43 × 79 | zzuf `maps/arcade/bn_dark_nebula` | CC BY-SA 4.0 |
| `arena_deadwood` | Deadwood | 88 × 36 × 87 | zzuf `maps/oitq/deadwood` | CC BY-SA 4.0 |
| `arena_colosseum` | Colosseum | 147 × 29 × 119 | Generated by `scripts/colosseum.py` | Own work |

The four third-party maps are adapted from [zzuf-maps](https://github.com/zzufx/zzuf-maps). The
adapted `.nbt` files **remain under CC BY-SA 4.0** regardless of the mod's own licence. Shipping a
map inside the jar is redistribution, so `THIRD-PARTY-NOTICES.md` must travel with it. Full terms
and the change list are in that file.

The Colosseum is the only map whose fighting area is smaller than its bounding box: the sand floor
is 100 × 80 inside a 147 × 119 box, insets 23 / 19. The boundary curtain circles the fighting area
only — otherwise sitting in the stands counts as still being in the arena.

**Map order is part of the wire format.** `e.template` stores an index, so reordering makes every
saved rule set point at a different map. **Append only, never insert.** Three maps were once
retired (Trial Chambers, Thistle Bridge, Avalon) and deleted outright instead of being left as gaps —
the cost was that rule sets saved before that change resolve to a different map. If a map is retired
after release, **leave a gap**.

## 2. Asset directory

`arena-src/` is a local asset directory (not in version control) holding only the
sources needed to rebuild the shipped maps:

```
arena-src/
└── _zzuf/                     Trimmed copy of zzuf-maps
    ├── README.md              Upstream readme (for attribution)
    └── maps/
        ├── arcade/bn_dark_nebula/
        ├── gs/gs_earthborn/
        ├── oitq/deadwood/
        └── tdm/fun_house/
```

Each source directory carries its own `LICENSE.txt`, `level.dat`, `map.xml`, `map.png` and
`region/`. The other 43 directories, the upstream `.git` and `includes/` were deleted
(46 MB → 1.3 MB); the four that remain are byte-for-byte identical to upstream.

Early evaluation also used four candidate maps (battle-arena, circular-white-quartz-arena,
gamarudos-gladiator-arena, pvp-castle), all of which were rejected; the `.litematic` files have been
deleted. Their only purpose was proving the `litematic` reader correct — the block-by-block
comparison results are recorded in
[`../archive/research/PvPocket-场地模板-调研与工具.md`](../archive/research/PvPocket-场地模板-调研与工具.md),
and re-downloading a schematic of the same name reproduces them.

## 3. Conversion pipeline

The source material is a Minecraft world save (`region/*.mca`); the output is a vanilla structure
template (gzip NBT).

```bash
# 1. Probe: confirm size and palette
python scripts/world2struct.py probe arena-src/_zzuf/maps/tdm/fun_house --palette

# 2. Convert: write into the resources directory
python scripts/world2struct.py convert arena-src/_zzuf/maps/tdm/fun_house \
    --out src/main/resources/data/pvpocket/structure/arena_fun_house.nbt

# 3. Verify: block-by-block comparison against a third-party reader
python scripts/arena-verify.py

# 4. Optional: render a top-down view to confirm orientation by eye
python scripts/arena-map.py
```

The six things conversion does — which is also the "indicate changes" list CC BY-SA requires:

1. **Format conversion**: world save → structure template, preserving block positions, states and
   palette. 1.8 saves use numeric ids; these are flattened to 1.13+ names via a legacy id table.
2. **Strip objective-mechanic blocks**: `barrier`, `light`, `structure_void`, `structure_block`,
   `jigsaw`, `command_block`. They encode PGM region definitions and command logic, which PvPocket
   does not use and which can be abused from inside the arena.
3. **Block substitution**: blocks absent from 1.21.1 become equivalents (`pale_oak_*` → `oak_*`,
   `waxed_exposed_copper_bars` → `iron_bars`, 26 entries in total).
4. **Gravity block stabilisation**: `*_concrete_powder` → `*_concrete`, which otherwise collapses
   the moment it is placed.
5. **Unstable block removal**: pressure plates, torches and rails that detach on their own, `fire`
   that burns out, `tripwire` that breaks when walked through. Keeping them lets the arena drift
   permanently away from its own baseline.
6. **Entity and block-entity removal**: item frames, armour stands, chests and their contents. The
   arena is blocks only.

**The verification reference must be a third-party implementation.** The first version of
`arena-verify.py` compared against its own generated `.nbt`; 80/80 passed while both sides were
wrong in the same way. It now reads the source independently through `litemapy` and compares.

## 4. Colosseum

`scripts/colosseum.py` is a generator, not a converter: ellipse inside ellipse, ten rows of stands,
a 15-block outer wall, two gates on the X axis. It exists because no redistributable colosseum
could be found — PGM community repositories publish XML without saves, and work on the usual map
sites is all-rights-reserved by default, which cannot go inside a jar.

```bash
python scripts/colosseum.py --out src/main/resources/data/pvpocket/structure/arena_colosseum.nbt
```

The generator's `A_ARENA = 50` and `A_OUT` set the ratio between fighting area and bounding box;
changing them changes the shape. **After changing them you must update the inset parameters on
`ArenaMaps.COLOSSEUM`** (23 / 19), or the boundary curtain lands behind the stands.

Only **one block** of podium wall separates the sand from the first row of stands, and the
preparation barrier ring is drawn exactly one block outside the fighting area. That ring used to be
written unconditionally, so every round dug the podium wall out to air at the same spot, and the
teardown could only turn it back into air (the write is wrapped in `suppressRecording`, so
`revertRegion` cannot restore it either). The ring now only writes over **air**: a solid block is
already an obstacle and the ring has nothing to add there. A save that was already dug out heals on
the next restart or `arena reset`, both of which re-paste the template.

## 5. Plots and copies

The duel dimension is void, carved into a 4×4 grid. Each cell is 160 blocks square and cell centres
are 256 apart, which leaves 96 blocks of empty space between cells so two maps never grow into one
another. A map owns one cell by its index in `ArenaMaps.ALL` — that index is its *home*, and it
never moves.

A map may own more than one cell. **Copies are capacity**: a duel leases one cell, and a map with
every cell leased is full — the panel greys it out. Each extra copy is one more duel of that map
running at the same time.

| Map | Default copies |
| --- | --- |
| `flat` | 4 |
| `arena_colosseum` | 2 |
| everything else | 1 |

The defaults only decide the initial layout of a **fresh save**. To change the count (operator only,
permission level 3):

```bash
/pvpocket arena copy flat 2            # two more flat plots
/pvpocket arena copy arena_colosseum   # no count means one
```

The cell numbers of the copies are recorded in `<save>/pvpocket/arena.json`, and **the number is the
address**: the third flat plot is always the same coordinates, across restarts, across
`arena reset`, and across map changes. That is the whole reason to copy a structure instead of
pasting a fresh one per round — an operator can `/tp` to a remembered spot and find the scene.

- Copies of a non-flat map are **pasted when the command runs**, so you can fly over and look.
- Copies of a flat map **reserve a cell without paving it**: their platform size comes from the
  rules (16–224) and is not decided until somebody needs it. The first duel that lands on one paves
  it.
- `arena reset` returns **every** copy to the reserved state: it clears the dimension and re-stamps
  only the first copy of each map, so a copy is re-pasted by the first duel that lands on it. Cell
  numbers do not change, so a `/tp` spot stays valid.

The grid holds 16 cells. The six built-in maps take one each, leaving ten for copies. When it is
full, `copy` refuses and reports the cell count — that means the dimension needs to be bigger, not
that more copies should be forced in.

**A plot may spill out of its cell.** The plot is centred in the cell, so a plot wider than the cell
reaches into the gap on both sides; the hard limit is "must not touch the neighbour", i.e.
`MAX_SIZE_XZ = 256 − 32 = 224`. That is why `ArenaRegion.reset()` clears the **union** of cell and
plot: clearing only the cell would leave the outer ring of a previous 224-wide flat arena standing
in the gap.

The startup warm-up stamps only the **first** copy of each map. Copies are capacity, not exhibits:
pre-stamping them all would double both the startup stall and the disk the dimension takes, and
nobody flies out to look at an empty copy.

## 6. Adding a map

1. **Check the licence first.** Shipping inside the jar is redistribution, so all-rights-reserved
   work cannot be included.
2. Put the source into `arena-src/` and run the four steps above.
3. Add a `public static final ArenaMap` to `ArenaMaps`, using the bounding box the converter
   reports — do not hand-write an estimate. `ArenaMap.paste` re-checks and warns on a mismatch, but
   by then the panel has already laid itself out against the wrong size.
4. **Append** to the end of `ArenaMaps.ALL`; do not insert.
5. Add one `pvpocket.map.<id>` entry to each of the two language files.
6. Update the table and change notes in `THIRD-PARTY-NOTICES.md`.
