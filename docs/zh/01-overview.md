# PvPocket 概览

> 规范文档 · 中文版。英文版：[`../en/01-overview.md`](../en/01-overview.md)

## 这是什么

PvPocket（口袋决斗）是一个 Minecraft Fabric 1.21.1 模组，为生存服提供**随时可开的一场决斗**：
双方协商规则、进入独立维度、在复刻的原版机制下对局、结束后一切复原。

它不追求做服务器核心玩法，也不做匹配大厅。定位是一句话：**两个人想打一场，三十秒内能开打，
打完什么痕迹都不留。**

## 四个核心决定

### 1. 规则先协商，后开打

发起方打开规则面板，设完条件发给对方；对方可以接受、可以改后再发、也可以拒绝。
双方同意的是一份**带版本号的规则快照**（39 条），不是一个开关列表。规则改动会递增版本，
旧版本上的同意不算数。

这条决定的代价是每场决斗前多一次交互。收益是「被拉进一场 5 局 3 胜、还开了友伤的决斗」
这种事不会发生。

### 2. 服务端权威，客户端只表达意图

客户端从不决定任何状态。所有包都是 intent：`RulesSubmitPayload` 说「我想接受」，
服务端重新核对会话状态、配装指纹、地图占用之后再决定是否真的开始。战斗数值、
击退、护甲全部在服务端结算。

这条让「改客户端就能开挂」的空间被压到只剩输入本身。

### 3. 对局结束，世界复原

进场前对参与者做完整快照（位置、背包、生命、饥饿、状态效果、经验、游戏模式），
结束后逐项还原。场地按分区租用，本局内被改动的方块记录在案，结束时分批复原。

任何一条复原路径失败都会让玩家永久丢失物品，所以快照与恢复走的是独立存储
（`<world>/pvpocket/`），并在启动时做一次对账。

### 4. 一个维度，多个分区

所有地图并排放在同一个决斗维度的不同格子里，每格 16 格间距。选图 = 传送到固定坐标，
不是把结构粘贴到原点。这样多场决斗可以真正同时进行，且互不可见。

## 功能边界

**有**：协商式规则、1.8 与现代表两种战斗模式、多局赛制、个人配装编辑、观战（含相机绑定）、
掉线兜底、地形保护与复原、滞留保护、场地重建。

**没有**：匹配与排队、排行榜与统计持久化、跨服、旁观者聊天频道、回放。
